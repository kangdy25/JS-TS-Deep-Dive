# 컴포넌트 분리 (Component Separation)

프론트엔드 프레임워크를 사용하며 "언제 나눠야 하는가?"라는 분리 시점은 중대한 사안이다. 코드를 언제 어떻게 나눠야할지 고민하고 정리하고 개선하는 과정은 중요한 문제 해결 과정이다.

## 컴포넌트를 분리해야 하는 이유

컴포넌트를 나눈 중요한 기준에 "재사용 가능성과 복잡성"이 있다. 이는 중복된 UI와 복잡한 UI를 다룰 때 컴포넌트 분리를 고민해야 함을 의미한다.

## 재사용 가능한 컴포넌트

예측 불가능한 미래의 변화에 잘 대응할 수 있도록 설게해야 하기 때문에 재사용을 고려하여 컴포넌트를 만드는 것은 매우 어렵다. 재사용을 위한 컴포넌트를 설계하기 위해서는 다음의 사항들을 고려해야 한다.

1. 재사용 가능하다는 것은 일반적이라는 것
2. HTML 요소의 재사용성
3. 안정적인 재사용성
4. 배치 및 스타일 재사용성
5. 컴포넌트가 재사용 가능하다는 것

## 복잡한 컴포넌트

여러 책임을 가진 컴포넌트는 복잡해진다. 이러한 컴포넌트는 높은 결합도로 인해서 상호작용의 예측을 어렵게 만든다. 따라서 컴포넌트를 책임에 맞게 분리하여 문제를 단순화해야 한다.

## 렌더링 성능

재사용성과 복잡성 외에 렌더링 성능으로 인하여 컴포넌트를 분리하기도 한다. 하나의 컴포넌트에 서로 영향을 주지 않는 상태가 여럿이 있다면 불필요한 렌더링이 발생하여 성능이 저하될 수 있다.

빈번하게 상태를 갱신하는 요소를 포함하는 컴포넌트의 경우 별도로 분리하면 성능을 개선하는 등의 긍정적인 효과를 기대할 수 있다.
