# 추상화 (Abstraction)

> [!note]
> **추상화(Abstraction)**: 정보를 선별하거나 일반화하는 과정으로, 복잡한 정보에서 필요한 부분만 남기고 단순화하는 과정이다.

프로그래밍에서 추상화는 코드를 함수로 분리하는 과정으로 볼 수 있다. 추상화 결과, 정보를 사용하는 주체는 구제적인 코드가 아니라 인터페이스에 의존하게 되며 코드는 이전보다 유연해진다.

## 추상화 수준 (Abstraction level)

> [!note]
> **추상화 수준(Abstraction level)**: 추상화 수준은 정보가 얼마나 선별되었고 일반화되었는지에 대한 지표로, 추상화 수준이 높다는 것은 일반화가 많이 이루어졌다는 것을 의미한다.

예를 들어, SQL 문법을 직접 사용하여 데이터를 가져오는 코드는 구체적이기에 추상화 수준이 낮다고 볼 수 있고, 함수를 포함하는 더 큰 기능의 함수나 객체를 사용할수록 추상화 수준이 높아진다.

추상화는 가지고 있는 정보 중 상황에 따라 필요한 정보만 선별 또는 일반화하는 과정이며 정보를 선별하고 일반화할수록 추상화 수준은 높아지고 반대의 경우 추상화 수준은 낮아진다.

## 추상화 계층 (Abstraction layer)

> [!note]
> **추상화 계층(Abstraction layer)**: 추상화를 통해 알아야 할 정보와 몰라도 될 정보를 나눌 때 생기는 경계를 말한다.

추상화는 필요한 정보(인터페이스)만 남기고 불필요한 정보(내부 구현)를 제거하여 복잡한 문제를 단순하게 만들며, 각 계층은 상위 계층에서 알아야 할 정보만 노출하고 하위 계층의 세부 사항은 상위 계층이 알지 못하도록 숨긴다.

## 적절한 추상화 수준

적절한 추상화 수준을 고민하는 것은 개발자에게 필연적이다. 다음은 적절한 추상화 수준을 선택할 때 도움이 되는 내용이다.

1. 적절한 추상화를 위해서는 지식과 경험이 필요하다.
2. 지나치게 예측하지 않는다.
3. 정보가 쌓이도록 두는 것보다 추상화하는 것이 낫다.
4. 추상화에는 절대적으로 올바른 정답이 없으며, 최선의 답을 단번에 찾는 경우도 드물다.
5. 최초의 추상화는 시간과 상황이 변하며 개선되어야 한다.
