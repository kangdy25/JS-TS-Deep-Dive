# 스타일 (Style)

프론트엔드에서 스타일은 다루기 쉬워보이나 어느 순간 가장 골치 아픈 문제를 만든다. CSS 선택자가 겹쳐 원하는 스타일이 적용되지 않기도 하고 우선순위를 따져야 할 만큼 동일한 스타일이 여러 곳에 중복으로 정의되기도 한다.

## 스타일 결합자로 영향 범위 제한하기

CSS의 어려움 중 하나는 "스타일의 영향 범위를 예측하기 어렵다"라는 것이다. 스타일은 전역적으로 정의되고 적용되며 그 규칙들 사이에 의존성이 쉽게 발생한다. 이러한 문제를 해결하는 가장 기본적인 방법은 CSS 결합자(Combinator)를 사용하여 스타일의 적용 범위를 특정 요소 및 자손으로 한정하는 것이다.

이는 코드의 변경으로 인한 영향을 제한하기 위해 캡슐화하는 것과 유사하며, 여러 스타일 규칙을 하나의 상위 선택자 아래에 그루핑하여 스타일의 응집도를 높인다.

## 스타일 책임 분리하기

스타일의 책임을 분리한다는 것은 요소의 위계에 따라 스타일을 다르게 적용한다는 것이다.

## 인지 부하를 낮추는 스타일 작성법

스타일은 한 줄에 하나를 정의하게 되는데, 따라서 스타일을 작성하다보면 수백 줄은 금방 넘어가고 규모가 이렇게 커지면 CSS 코드를 이해하기 어려워진다.

이때 스타일 코드를 작성하는 몇 가지 규칙을 정의하면 대규모 스타일을 이해하는데 필요한 인지 부하를 크게 낮출 수 있다.

1. 스타일 속성의 순서를 정하기 (레이아웃 -> 크기 및 여백 -> 시각적 속성 -> 폰트 및 텍스트 ...)
2. 상태에 따른 스타일을 명확하게 분리하기 (활성화, 비활성화, ...)
3. 스타일과 요소 간의 순서를 맞추기 (EX: .product-card -> .product-card > img ...)

결국 필요한 정보를 효율적으로 찾고 효과적으로 다루기 위한 것이다. 이러한 방법들의 목적은 스타일 뿐만 아니라 일반 코드에서도 동일하다.
