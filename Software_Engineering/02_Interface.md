# 인터페이스 (Interface)

> [!note]
> **인터페이스**: 인터페이스는 서로 다른 두 개의 시스템, 장치 사이에서 정보나 신호를 주고받는 경우의 접점이나 경계명이다. 즉, 인터페이스는 두 대상이 서로 만나서 소통하고 작용하는 공간이다.

인터페이스는 다음의 중요한 특징을 가진다.

1. 인터페이스는 상호작용 방법을 알려주기 위한 공개된 부분이다.
2. 인터페이스를 준수하기만 하면 그 외의 사항에 대해서는 신경 쓸 필요가 없다. (인터페이스만 준수한다면 구현은 자유하다.)

## 사용자 인터페이스 (User Interface)

**사용자 인터페이스**는 사람(사용자)과 컴퓨터 시스템 사이의 의사소통 매개를 의미한다. UI를 개발하는 프론트엔드 개발자는 반드시 인터페이스로 공개할 것과 공개하지 않을 것의 경계를 명확히 해야한다.

적절한 사용자 인터페이스는 다양한 상황과 환경에서도 사용자가 서비스를 이용할 수 있는 방법을 제공해야 하며, 외부로부터 접근할 수 있는 것과 접근을 제한해야 하는 것을 신중하게 선정해야 한다.

## 함수와 인터페이스

인터페이스는 여러 함수가 공통으로 구현해야 하는 구조를 정의(추상화)함으로써 이를 구현하는 함수들을 하나의 추상화된 개념으로 이해할 수 있도록 하는 정보이다.

인터페이스를 정의하면 로직의 세부 코드를 보기 전, 코드의 역할과 사용법을 빠르게 파악할 수 있으며 세부 로직의 결합이 제한된다. 즉, **구현이 아닌 추상(인터페이스)에 의존하게 된다.**

## 단일 구현을 위한 인터페이스

인터페이스와 인터페이스를 준수하는 구현이 하나씩 존재하는 경우, 이를 단일 구현을 위한 인터페이스라고 한다. 이런 경우에는 보통 인터페이스를 만들지 않는 것이 권장된다.

## 테스트와 인터페이스

테스트 환경에서 인터페이스는 테스트하려는 대상을 제외한 나머지 구현을 교체할 수 있도록 돕는다. 이를 통해 테스트 대상이 불필요하게 의존하는 요소들을 제거하여 효율적인 테스트 작업을 수행할 수 있다.

API 요청은 대표적인 번거로운 테스트 요소 중 하나이다. 이러한 번거로운 API 호출 테스트는 인터페이스를 정의하고 구현체를 단순하게 바꿈으로 검증 과정을 단축시킬 수 있다.

## 개발자와 인터페이스

인터페이스는 코드 뿐만 아니라 개발자에게도 객체를 이해하는데 도움이 되는 정보를 제공해야하며, 주석이나 JSDoc 등을 사용하여 추가정보를 제공하는 것은 유용하다.
