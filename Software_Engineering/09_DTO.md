# 데이터 전송 객체 (DTO)

> [!note]
> **데이터 전송 객체(DTO)**: 특정 계층에서 사용하던 데이터를 다른 계층이 이해하기 쉬운, 정해진 구조로 변환해서 전달하는 객체

## DTO의 이해

DTO를 사용하여 각 로직의 관심사를 분리하고, 불필요한 데이터 확산을 막고, 데이터 가공 로직이 복잡해져도 렌더링 로직에 영향을 주지 않게 할 수 있다.

정의된 DTO는 하나의 계층으로서 기존 데이터 구조의 변경이 사용하는 모듈에 직접 전달되지 않도록 막는다.

## DTO 사용 시 주의사항

DTO를 사용할 때 전달(Transfer)을 매핑(Mapping)이나 변환(Transform)과 혼동하지 말아야 한다. DTO는 데이터 구조 자체이기에 데이터 구조 표현에 맞춰야 한다. 또한 데이터의 유효성을 판단하거나 데이터를 가공하여 반환하는 공개 메서드를 포함하면 안된다.

즉, DTO는 순수하게 데이터를 전달하고 구조화하는데 집중하고 그 외의 로직은 별도로 분리해야 한다.

또한 정확히 동일한 데이터 구조를 사용하는 여러 모듈이 하나의 DTO에 의존하는 것은 문제가 없으나 DTO가 여러 모듈의 데이터 구조를 지원하는 방향으로 설계하고 구현하면 코드가 지나치게 복잡해지기에 주의해야 한다.

## DTO와 API

프론트엔드에서는 DTO를 API 응답을 처리하기 위해 자주 사용한다. 외부에서 데이터를 가져오는 것과 같이 데이터에 대해 프론트엔드 측에서 주도권을 갖기 어려운 경우 DTO의 활용도는 더욱 올라간다. 다만, 모든 데이터 구조에 대해 기계적으로 DTO를 정의하면 불필요한 계층이 생겨 코드의 복잡도를 높일 수 있게 된다.
