# 📌 Chapter 5: 브라우저 렌더링 최적화 및 로직 개선 (Rendering & Execution Advanced)

프레임 유실을 잡아 60FPS의 매끄러운 화면을 선사하고, 자바스크립트 엔진 연산 병목을 제거하여 무겁거나 브라우저 탭이 정지되는 현상을 방어하는 하이엔드 최적화 기법을 다룹니다.

## 1. 브라우저 레이어 구성과 GPU 하드웨어 가속

브라우저는 화면을 여러 장의 독립된 투명 레이어(Layers)로 나누어 그린 뒤 최종 렌더링 시점에 합성(Composite)합니다. 특정 요소가 독자적인 그래픽 레이어로 분리되면, 그 요소의 스타일 변화가 주변 요소의 레이아웃(Reflow)이나 페인트(Repaint) 연산에 직접적인 영향을 주지 않고 GPU 하드웨어 가속을 통해 매우 빠르게 처리됩니다.

### 1) 하드웨어 가속 활성화 CSS
* **과거 해킹 패턴**: `transform: translate3d(0, 0, 0)` 또는 `translateZ(0)`를 부여해 레이어를 강제 형성
* **모던 표준 패턴**: CSS `will-change` 속성을 활용해 레이어 배정을 브라우저에게 선제적으로 유도

```css
.animated-panel {
  will-change: transform, opacity; /* 애니메이션 동작 시의 레이어 격리 최적화 경고 */
  transition: transform 0.3s ease-out;
}
```

> [!CAUTION]
> `will-change`를 페이지의 모든 요소에 무분별하게 적용하면 브라우저는 다수의 비디오 메모리(VRAM) 레이어를 관리해야 하므로, 모바일 웹 브라우저 탭이 예기치 않게 강제 종료(Crash)되거나 전반적인 렌더링 성능이 파괴되는 역효과가 발생합니다. 반드시 상시적인 고해상도 애니메이션 연산이 따르는 극소수 타겟 요소에만 선별 적용해야 합니다.

## 2. Layout Shift (CLS) 완벽 회피 방침

### 1) 스켈레톤 UI (Skeleton Screen) 패턴
서버로부터 데이터가 아직 응답되지 않았을 때 콘텐츠 레이아웃 높이 영역을 0으로 비워두지 않고, 최종 로드될 엘리먼트와 유사한 회색 뼈대(스켈레톤)를 먼저 노출하는 기법입니다. 뒤늦게 데이터가 들어와 돔 높이가 팽창하는 CLS 현상을 막고 긍정적인 체감 로딩 피드백을 전달합니다.

### 2) Aspect Ratio (종횡비) CSS 활용
반응형 레이아웃 환경에서 가로 너비(Width)가 가변으로 변하더라도 최종 이미지/비디오가 렌더링되기 전에 높이를 사전에 유지하도록 돕는 모던 CSS 속성입니다.

```css
.video-frame-container {
  width: 100%;
  aspect-ratio: 16 / 9; /* 가로 가변에 맞춰 16:9 높이 공간을 무조건 선점하여 CLS 방어 */
  background-color: #e5e7eb; /* 회색 스켈레톤 배경 적용 */
}
```

### 3) CSS `content-visibility: auto` 적용
화면 뷰포트 바깥의 저 아래(예: 푸터, 하단 댓글 목록 등)에 위치한 복잡한 돔의 페인팅 연산을 완전히 건너뛰도록 브라우저에게 명령하는 기능입니다. 영역 레이아웃 형태는 유지하되 드로잉 리소스를 절감하므로 초기 로드 효율을 극단적으로 끌어올립니다.

## 3. 병목 함수 로직 개선 및 실행 제어

자바스크립트는 싱글 스레드(Single Thread)로 구동되기 때문에 무거운 연산 로직이 스레드를 점유하면 브라우저 UI 자체가 얼어버리는 프리징(Freeze)이 발생합니다.

### 1) 이벤트 빈도 제어 (Debounce & Throttle)
* **디바운스 (Debounce)**: 짧은 시간 연속해서 발생한 이벤트(예: 검색창 타이핑) 시 매번 동작하지 않고, 타이핑이 끝나고 특정 주기(예: 300ms) 동안 추가 이벤트가 안 들어올 때 최종 결과에 대해 단 1회만 콜백 실행.
* **쓰로틀 (Throttle)**: 무수히 연속된 이벤트(예: 스크롤 이벤트 감지)가 터지는 와중에도, 지정된 주기(예: 100ms)마다만 1회 실행하도록 락(Lock)을 걸어 실행 빈도를 제한.

### 2) Web Worker를 통한 연산 분산
정렬, 통계 연산, 대량 JSON 파싱 등 UI 갱신과 무관한 헤비 CPU-bound 자바스크립트 로직은 메인 렌더링 스레드를 방해하지 않는 백그라운드 **Web Worker 스레드**로 이전(오프로드) 처리합니다.

```typescript
// worker.ts (백그라운드 스레드 파일)
self.onmessage = (e) => {
  const result = heavyComputation(e.data); // 무거운 루프 연산
  self.postMessage(result); // 처리 결과를 메인으로 재전송
};
```
메인 스레드에서는 `new Worker()`로 인스턴스를 열고 `postMessage`와 `onmessage` 이벤트 리스너를 활용해 논블로킹 통신을 설계합니다.
